# 03 결과

## 1. 버그: 실제 원인 / 고친 방법
- **실제 원인**: `PoolManager`의 `private Canvas canvasRoot`가 어디에서도 대입되지 않아(grep 확인) 항상 null → `ReleaseUI`의 해제 콜백(281행 `canvasRoot.transform`)이 **어떤 UI를 반납해도** NullReferenceException. 기존 `InventoryUI`는 반납한 적이 없어 드러나지 않았던 기존 매니저 버그이며, `TestInventoryWindow` 프리팹 문제가 아님.
- **고친 방법**: 매니저는 수정하지 않고 `TestInventoryManager`가 `CloseWindowUI`(풀 반납)를 쓰지 않도록 함. 처음 한 번만 `ShowWindowUI`로 만들고, 이후는 창을 `SetActive(false/true)`로 끄고 켬(켜질 때 `OnEnable`에서 칸 재생성·선택 초기화).
- **사용자 추정 확인**: 맞음. 예외가 `CloseWindow()` 중간에서 나서 `IsOpen=false`·커서 복구가 실행되지 않아 `TestController`가 계속 입력을 막았음.
- **방어 처리**: `CloseWindow()`를 `try { 창 끄기 } finally { IsOpen=false; 커서 복원 }`으로 변경.

## 6. 사용자가 직접 확인할 것
- 닫기 버튼(X)/I 키/우측 상단 버튼으로 열고 닫아도 예외 없음, 닫은 뒤 캐릭터 정상 동작
- 여러 번 열고 닫아도 칸 수 유지, 선택 초기화
- 12칸·16칸에서 창이 화면/패널 밖으로 안 넘치는지, 선택 칸 노란 굵은 테두리·올리브 바탕
- 한글/폰트 표시, 우측 상단 버튼이 항상 보이고 창이 열리면 창이 그 위에 그려지는지
- LookOff를 누른 채 버튼으로 열기 → 닫기 → LookOff 해제 시 커서가 다시 잠기는지

## 7. 확인 필요
1. **LookOff와 커서 복원**: 열 때 커서 상태(보통 Locked, LookOff 중이면 None)를 저장해 닫을 때 복원하는 방식. LookOff를 누른 채 열고 열린 동안 LookOff를 놓으면 닫을 때 None으로 복원되지만, 다음 프레임 `TestController.LockOff`가 다시 Locked로 맞춰 실제 문제는 없을 것으로 보임(테스트 안 함).
2. 우측 상단 버튼은 **클릭하려면 LookOff가 필요**함(지시문대로). 항상 마우스로 누르게 하려면 기존 커서 정책 변경이 필요해 하지 않음.
3. 그림(완성 화면 예시)을 직접 보지 못해 위치·비율은 지시문 설명 기준. 차이가 있으면 알려주세요.
4. 창을 풀에 반납하지 않아 풀의 활성 카운트에는 창 1개가 계속 남음(기능 영향 없음, 매니저 버그 회피 때문).
