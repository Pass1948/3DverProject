# 01 결과 — 조사

> 전제 차이: 지시문의 "서바이벌 슈터 / PlayerCtrl / FireCtrl"은 프로젝트에 **존재하지 않음**. 실제는 `WorkSpace` 아래 BaseCopy(공용 틀) + Game1_SlimeRancher + Game2_PEAK 구조. 아래는 실제 코드 기준 (자세한 건 5번).

## 1. 재사용 가능한 매니저 멤버
위치: `WorkSpace\BaseCopy\Scripts\Managers\`
- **싱글턴**: `GameManager` — `private static instance`, `public static GameManager Instance`. `[DefaultExecutionOrder(-100)]`, `DontDestroyOnLoad`. Awake에서 자식 매니저 6개를 코드로 생성(씬에 배치 안 함).
- **정적 접근자(전부 public static)**: `GameManager.Resource / Pool / UI / Event / Sound / Unit`
- **EventManager** (`GameManager.Event`) — `Subscribe/Unsubscribe/Publish` (인자 0~3개 제네릭). enum `EventType`(Constants.cs)에 `Spawn, SelectSlot, SlotChanged, StaminaChanged, ClimbCheck, InteractText, InfoButtonText`. 새 이벤트 추가하려면 enum 수정 필요(= 기존 파일 수정) → 가급적 쓰지 않거나 확인 필요.
- **UIManager** (`GameManager.UI`) — public: `ShowWindowUI<T>(T | string path)`, `CloseWindowUI(WindowUI)`, `SelectWindowUI`, `ShowPopUpUI<T>`, `ClosePopUpUI`, `InstantsWindowUI/PopUpUI`, `EnsureEventSystem`, `Recreated`, `Clear`. Canvas 필드(`windowCanvas`, `popUpCanvas`)는 **private** (외부 접근 불가).
- **ResourceManager** (`GameManager.Resource`) — `Load<T>(path)`, `Instantiate<T>(...)` 오버로드, `Destroy(...)`. 경로는 `Resources/` 기준.
- **PoolManager** (`GameManager.Pool`) — `Get/Release/GetUI/ReleaseUI`.
- **UnitManager** (`GameManager.Unit`) — `Game1Player`, `Game2Player` 프로퍼티(public).
- **Canvas/UI 관련**: UIManager가 `Resources/UI/Canvas.prefab`을 2개(WindowCanvas order 10, PopUpCanvas order 100) 생성. EventSystem이 없으면 `Resources/UI/EventSystem.prefab` 생성. 베이스 클래스 `BaseUI`(TMPro, `Dictionary<string,Button/TMP_Text/RectTransform>` 보유), `WindowUI`, `PopUpUI` 존재 → 새 인벤토리 UI를 `WindowUI` 상속으로 만들면 매니저 그대로 이용 가능.
- **일시정지 / 입력 차단 / 커서 상태 관리**: 매니저에 **없음** (`Time.timeScale`, `Cursor` 사용처 grep 0건 — 매니저 쪽). 커서 처리는 각 플레이어 스크립트에 개별 존재.

## 2. 플레이어 입력 처리 위치 (발사 / 회전)
**입력 방식: 새 Input System** (`ProjectSettings activeInputHandler: 1` = Input System만, `com.unity.inputsystem 1.18.0`). `Input.GetKeyDown` 계열은 쓸 수 없음 → 인벤토리 열기 키는 `Keyboard.current` 또는 InputAction 사용.

**Game1_SlimeRancher** (`Script\Gun\Controller.cs`, 클래스 `Controller`, 같은 오브젝트에 `PlayerInput` 부착)
- 발사(흡입): `Update→CheckButtons()`에서 `attackAction.IsPressed()` → `isAttacking`; `FixedUpdate`에서 `Fire()` 호출
- 마우스 회전: `OnLook(InputValue)`(PlayerInput 메시지) → `lookDelta`; `Update→MouseRotate()`, `LateUpdate→MoveMouse()`
- 커서: `Start`에서 Locked/hidden, `LockOff()`에서 `LookOff` 액션 누르는 동안 해제(None/visible). `isLookOff`가 true면 `Fire`와 회전 모두 중단.
- 슬롯 단축키: `HandleSlotHotkeys()`에서 `Keyboard.current`, `EventType.SelectSlot` 발행.
- **이미 인벤토리가 있음**: `UI\InventoryUI.cs`(WindowUI 상속, TMP_Text 4칸), `Unit\Game1Inventory.cs`, `Data\Slots.cs`, `ItemDef(SO).cs`. 이걸 건드리면 안 되므로 TestInventory는 별도로 새로 작성.

**Game2_PEAK** (`Script\Unit\PeakRigidbodyController.cs`)
- 회전: `OnLook`→`lookInput`, `Update→UpdateLook()`; 이동/점프/클라이밍도 같은 클래스. 발사 개념 없음(아이템 잡기 `OnInteract`).
- 커서: `Start`에서 Locked/hidden, `OnLookOff(InputValue)`에서 누르는 동안 해제.

**BaseCopy 씬**에는 플레이어/총이 **없음**.

## 3. 기존 코드 수정 없이 막을 수 있는지
- **Game1 `Controller`**: **가능(조건부)**. 근거: ① 컴포넌트가 `MonoBehaviour`라 외부에서 `GameManager.Unit.Game1Player.controller.enabled = false` 가능 — `Update/FixedUpdate/LateUpdate`가 모두 멈춰 발사·회전 정지. ② 단, 이 방식은 `Start`에서 잠근 커서를 **풀어주지 않으므로** 커서 해제(`Cursor.lockState = None`)는 인벤토리 쪽에서 직접 해야 함. ③ `enabled=false`여도 `PlayerInput`이 `OnLook` 메시지를 계속 보내 `lookDelta`가 쌓일 수 있음(메시지는 비활성 컴포넌트에도 전달됨) → 재활성화 직후 시점이 튈 가능성 있음. 완화책: `PlayerInput` 쪽에서 액션맵 전환(`playerInput.SwitchCurrentActionMap`)은 기존 액션 에셋에 UI 맵이 있어야 하므로 확인 필요.
- **대안**: `Controller`의 `isLookOff`(LookOff 액션)가 같은 효과(발사+회전 정지, 커서 해제)지만 private이고 사용자가 키를 누르고 있어야 함 → 외부 제어 **불가**.
- **PEAK `PeakRigidbodyController`**: 클래스 단위 `enabled=false` 가능. 단 이동/점프 전체가 멈추고 커서도 안 풀림. 이번 과제 대상 씬이 PEAK인지 확인 필요.
- 매니저에 쓸 수 있는 "일시정지/입력차단" 상태값은 **없음**.
- 결론: 기존 코드 수정 없이 **새 스크립트에서 `controller.enabled` 토글 + `Cursor` 직접 제어**로 가능. 새 입력 시스템이라 인벤토리용 열기 키는 `Keyboard.current` 사용.

## 4. 씬/환경 정보
- **Unity**: 6000.3.6f1. **uGUI 2.0.0** (`com.unity.ugui`, TMP 포함 통합). `Assets\TextMesh Pro\Resources` 존재(TMP Essentials 임포트됨). 기존 코드에서 `using TMPro` / `TMP_Text` 사용 중.
- **씬 후보**(복제용):
  - `Assets\WorkSpace\BaseCopy\Scenes\MainScene.unity` — Main Camera, Directional Light, Global Volume, GameManager만 있는 **빈 베이스 씬**. Canvas/EventSystem/TMP 없음(런타임에 UIManager가 생성). **가장 유력**.
  - `Assets\WorkSpace\Refactoring\Scene\MainScene.unity` — BaseCopy와 동일 구성(GameManager 포함).
  - `Assets\WorkSpace\Game1_SlimeRancher\Scene\MainScene.unity` — Player(PlayerInput+Controller) 있음, 씬 파일 내 Canvas 없음(런타임 생성).
  - `Assets\WorkSpace\Game2_PEAK\Scene\Scenes\MainScene.unity` — git에서 수정 상태(M)라 복제 시 주의.
- **씬 내 Canvas/EventSystem/TMP**: 어느 씬 파일에도 **직접 배치된 것 없음** (grep 0건). 런타임에 `GameManager→UIManager`가 `Resources/UI/Canvas.prefab`, `EventSystem.prefab`을 생성.
- **커서 잠금**: Game1 `Controller.Start`와 PEAK `PeakRigidbodyController.Start`에서 `Locked` + 숨김 사용 → **인벤토리 칸 클릭하려면 열 때 커서 해제가 필수**.
- **UnityMCP 가능**: 도구 있음 — `manage_scene`, `manage_gameobject`, `manage_components`, `manage_ui`, `manage_asset`, `manage_prefabs`, `create_script`, `read_console`, `refresh_unity`, `execute_menu_item`, `run_tests`, `find_gameobjects`. 실제 연결 상태(Unity 에디터 켜짐 여부)는 이번 단계에서 호출하지 않아 **미확인**.
