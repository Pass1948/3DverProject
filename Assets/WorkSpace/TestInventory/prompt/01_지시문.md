# 01 지시문 — 1단계: 기존 코드 조사 (읽기 전용)

## 배경
- 유니티 과제: 서바이벌 슈터 프로젝트에 **UI(Canvas) 인벤토리**(빈 칸 8개 이상, 키로 열기/닫기, 닫기 버튼, 칸 클릭 선택, 선택 번호 텍스트 표시)를 만든다.
- 작업 위치: `D:\Unity_Project\3DverProject\Assets\WorkSpace\TestInventory`
- 인벤토리용 스크립트는 **새로** TestInventory 안에 만들 예정이고, **기존 매니저는 이용만 한다.**
- 이번 1단계는 구현 전 **조사**다. 구현은 사용자 승인 후 `02_지시문.md`로 따로 지시한다.

## 절대 규칙
1. 이번 단계에서는 **어떤 기존 파일도 수정·삭제·생성하지 않는다.** (읽기만)
   - 예외: 결과 파일 `TestInventory\prompt\01_결과.md` 한 개만 작성한다.
2. 기존 매니저(GameManager, UIManager 등)의 코드 구조는 건드리면 안 된다. (이후 단계에서도 동일)
3. 확실하지 않거나 애매한 것은 임의로 판단하지 말고 결과 파일의 **"확인 필요"** 항목에 적는다.
4. 컴파일, 플레이, 테스트는 실행하지 않는다. 읽고 정리만 한다.
5. 채팅 응답은 **"완료"** 한 단어만 한다. 작업 내용은 채팅에 설명하지 않는다. 모든 내용은 결과 파일에만 적는다.

## 조사할 것
프로젝트 `Assets` 전체에서 아래를 찾아 읽는다. (파일 위치는 직접 검색)

### A. 기존 매니저 (GameManager, UIManager 등 `*Manager*.cs`)
- 싱글턴 접근 방식 (`instance` 등)과 접근 제한자
- 인벤토리 스크립트에서 **그대로 가져다 쓸 수 있는 public 멤버** (함수, 필드, 프로퍼티)
- 이미 Canvas/UI/TextMeshPro를 다루는 부분이 있는지 (있다면 어떤 오브젝트를 참조하는지)
- 게임 일시정지, 입력 차단, 마우스 커서 잠금 같은 상태를 관리하는 변수/함수가 있는지

### B. 플레이어 쪽 (PlayerCtrl.cs, FireCtrl.cs 등)
- 총 발사 입력(마우스 클릭)과 캐릭터 마우스 회전이 **어느 스크립트의 어느 함수에서** 처리되는지
- 입력 방식: 기존 Input Manager(`Input.GetKeyDown`)인지 새 Input System인지
- 코드를 **수정하지 않고** 이 둘을 막을 방법이 있는지 (예: 외부에서 컴포넌트 `enabled` 제어 가능 여부, 매니저에 이미 있는 상태값 활용 가능 여부)
  - 가능/불가능 여부와 근거만 적는다. 실제로 막는 코드는 작성하지 않는다.

### C. 씬과 프로젝트 환경
- 수업 플레이 씬 후보 파일 이름과 경로 (복제해서 테스트 씬으로 쓸 예정)
- 그 씬에 이미 있는 Canvas, EventSystem, TextMeshPro 사용 여부
- Unity 버전, TextMeshPro 패키지 설치 여부
- 마우스 커서가 현재 잠겨 있는지 (`Cursor.lockState` 사용 여부) — 인벤토리 칸을 마우스로 클릭해야 하므로 중요
- 이 환경에서 Unity를 MCP로 조작할 수 있는지(씬에 오브젝트 생성, 컴포넌트 추가 가능 여부). 가능한 도구 이름만 간단히 적는다.

## 결과 파일 작성
`D:\Unity_Project\3DverProject\Assets\WorkSpace\TestInventory\prompt\01_결과.md`

형식은 아래 제목 순서를 따르고, **짧게** 쓴다. 코드 전문을 붙이지 말고 파일명, 함수명, 멤버명만 적는다.

```
# 01 결과 — 조사
## 1. 재사용 가능한 매니저 멤버
## 2. 플레이어 입력 처리 위치 (발사 / 회전)
## 3. 기존 코드 수정 없이 막을 수 있는지
## 4. 씬/환경 정보
## 5. 확인 필요 (애매하거나 불확실한 것, 사용자 판단이 필요한 것)
```

작성이 끝나면 채팅에는 **"완료"** 만 보낸다.
