# 02 지시문 — 2단계: 인벤토리 구현

## 배경
- 5차 평가 과제: 게임 화면 위에 **UI(Canvas) 인벤토리**(빈 칸, 키로 열기/닫기, 닫기 버튼, 칸 클릭 선택, 선택 번호 텍스트)를 만든다. 아이템은 넣지 않는다.
- 평가는 **소스코드(.cs)와 그 안의 주석**으로만 한다. 그래서 주석(설계 메모)이 중요하다.
- 1단계 조사 결과(`prompt\01_결과.md`)를 전제로 진행한다. 이미 읽었다면 다시 조사하지 말고 필요한 부분만 확인한다.
- 작업 위치: `D:\Unity_Project\3DverProject\Assets\WorkSpace\TestInventory`

## 절대 규칙
1. **기존 매니저(GameManager, UIManager 등)와 기존 스크립트는 수정·삭제·이동하지 않는다.** (`Controller`, `InventoryUI`, `Game1Inventory`, `Slots`, `ItemDef` 포함) 기존 `EventType` enum에도 항목을 추가하지 않는다.
2. 새 스크립트와 씬은 모두 `TestInventory` 안에 만든다. **예외는 `Resources` 아래 인벤토리 프리팹 1개뿐**이다. 이 프리팹의 경로는 결과 파일에 적는다.
3. 새 클래스 이름 앞에는 `Test`를 붙여 기존 클래스와 겹치지 않게 한다. 새 `.cs` 파일은 UTF-8로 저장한다.
4. 원본 씬(`Game1_SlimeRancher\Scene\MainScene.unity`)은 열어서 수정하지 말고, **복제본에서만 작업**한다.
5. **컴파일 에러가 없는지까지만 확인한다.** (`read_console`) 플레이 테스트와 추가 점검은 하지 않는다. 사용자가 직접 한다.
6. 애매하거나 확실하지 않은 것은 임의로 판단하거나 기존 코드를 고쳐서 해결하지 말고, 결과 파일의 **"확인 필요"** 에 적은 뒤 그 지점에서 멈춘다. (특히 아래 "멈춰야 하는 경우" 참고)
7. 채팅 응답은 **"완료"** 한 단어만 한다. 작업 내용은 채팅에 설명하지 않는다.

## 만들 것

### 1. 씬
- `Game1_SlimeRancher\Scene\MainScene.unity`를 복제해 `TestInventory\TestInventoryScene.unity`로 만든다. (에디터에서 복제하는 방식으로 하고, 복제본에서 작업)

### 2. 인벤토리 UI (`GameManager.UI.ShowWindowUI` 사용)
- `WindowUI`를 상속한 **`TestInventoryUI`** 를 만든다. 기존 `InventoryUI`가 `BaseUI`의 이름 기반 바인딩을 어떻게 쓰는지 **읽어서 같은 방식**으로 따른다. (수정은 금지)
- 프리팹은 `ShowWindowUI`가 로드하는 `Resources` 경로 규칙을 확인해서 그 아래에 만든다. (예: 이름 `TestInventoryWindow`) 구성:
  - 패널(Image), 슬롯 영역(**Grid Layout Group**), 슬롯 버튼들, **닫기 버튼**, 선택 표시 텍스트(**TextMeshPro**), **확장 버튼**, 안내 문구 텍스트
- 처음 칸은 **4×2 = 8칸**, 슬롯 크기와 간격은 창 안에 가지런히 들어가게 한다.

### 3. 열기/닫기 담당 스크립트
- **`TestInventoryManager`** 를 만든다. 창이 닫혀 있으면 창에 붙은 스크립트의 `Update`가 돌지 않으므로, **항상 켜져 있는 씬 오브젝트**(예: `TestInventoryManager` 빈 오브젝트)에 붙인다.
- 열기/닫기 키는 **I**. 새 Input System이므로 `Keyboard.current`를 쓴다. (`Input.GetKeyDown` 사용 금지)
- 이미 열려 있으면 I로 닫고, 닫혀 있으면 열린다. 닫기 버튼으로 닫은 뒤에도 I로 다시 열려야 한다.
- 창이 열려 있는지를 외부에서 읽을 수 있게 `public static bool IsOpen`을 둔다.
- **열 때**: 마우스 커서를 해제(`Cursor.lockState = None`, `visible = true`). **닫을 때**: 커서를 원래 상태(잠금/숨김)로 되돌린다.
- 칸 수 같은 상태는 창이 닫혀서 파괴되어도 사라지지 않도록 **Manager 쪽에 보관**한다. 창을 다시 열 때 보관된 칸 수로 다시 만든다.

### 4. 칸 선택 (필수 기능)
- 선택된 칸은 **int 하나**로 기억한다. (선택 없음 = 0, 칸 번호는 1부터)
- 칸을 클릭하면: 모든 칸을 원래 색으로 → 클릭한 칸만 **노란색** → 선택 번호 저장 → 텍스트 갱신. 선택은 한 번에 하나뿐이다.
- 텍스트는 처음 열었을 때 **"선택: 없음"**, 칸을 선택하면 **"선택: N번 칸"**.
- 창을 닫았다 다시 열면 칸 수는 그대로이고 선택은 초기화("선택: 없음")된다.
- **UI 색과 텍스트는 매 프레임 바꾸지 않는다.** 클릭했을 때와 열 때만 갱신한다. (`Update`는 Manager의 키 검사에만 쓴다.)

### 5. 옵션 1 — 칸 늘리기
- 확장 버튼을 누르면 칸이 **4칸씩** 늘어난다. 최대 **16칸**까지.
- 최대에 도달한 뒤 누르면 더 늘어나지 않고 안내 문구("더 이상 늘릴 수 없습니다" 등)를 보여 준다.
- 늘어난 칸 수는 닫았다 열어도 유지된다.

### 6. 옵션 2 — 플레이어 연동 (복사본 방식)
- 기존 `Game1_SlimeRancher\Script\Gun\Controller.cs`는 **수정하지 않는다.** 이 파일을 `TestInventory`로 **복사**해서 **`TestController`** 를 만든다. (클래스 이름 변경, 나머지는 그대로)
- 복사본에만 아래를 추가하고, **추가한 위치마다 "인벤토리 연동 추가" 주석**을 단다.
  - 인벤토리가 열려 있는 동안(`TestInventoryManager.IsOpen`) **발사(흡입)를 하지 않는다.**
  - 인벤토리가 열려 있는 동안 **마우스 회전을 하지 않는다.** (입력이 쌓였다가 닫을 때 시점이 튀지 않게, 열려 있는 동안의 `lookDelta`는 버린다.)
  - 커서 처리는 `TestInventoryManager`가 맡으므로 `TestController`가 열려 있는 동안 커서를 다시 잠그지 않게 한다. (기존 `LockOff` 같은 커서 로직과 충돌하는지 확인)
- 복제한 씬의 **플레이어 오브젝트에서 기존 `Controller` 컴포넌트를 `TestController`로 교체**한다. (원본 씬의 플레이어는 건드리지 않는다.)

## 멈춰야 하는 경우 (결과 파일에 적고 중단)
- 플레이어의 `Controller`를 `TestController`로 교체했을 때, `UnitManager`/`GameManager.Unit` 등 **기존 매니저가 `Controller` 타입을 참조하고 있어서** 교체하면 동작이 깨질 것 같은 경우. (매니저 수정으로 해결하지 말 것)
- `ShowWindowUI`/`WindowUI`/`BaseUI`의 규칙 때문에 위 구성을 만들 수 없는 경우.
- Unity MCP 연결이 안 되거나, 에디터가 응답하지 않는 경우.
- 그 밖에 기존 코드를 수정하지 않고는 해결할 수 없다고 판단되는 경우.

## 주석 작성 규칙 (평가 대상)
- **모든 새 `.cs` 파일 맨 위**에 "이 스크립트가 하는 일"과 "어느 오브젝트에 붙였는지"를 주석으로 적는다.
- **`TestInventoryManager.cs` 맨 위**에 설계 메모 3종을 적는다. 내용은 **실제 구현과 일치**해야 한다.
  - `[기획 메모]`: 열기/닫기 키(I), 칸 수와 배치(4×2, 확장 시 4칸씩 최대 16), 선택 표시(노란색)와 각각 그렇게 정한 이유
  - `[사용한 UI]`: 만든 오브젝트와 붙인 컴포넌트, 각각의 역할, 인스펙터에서 연결한 것 (프리팹과 씬 양쪽)
  - `[설계]`: 칸들과 선택 번호를 무엇으로 기억하는지, 칸 클릭 시 처리 순서, 창을 열고 닫을 때 바뀌는 것, 칸 수를 Manager가 보관하는 이유
- 씬/프리팹에서 에디터로 만들고 연결한 내용도 위 `[사용한 UI]`에 적는다. (평가는 씬을 보지 않기 때문)
- 변수와 함수 이름은 의미를 알 수 있게 짓고, 중요한 부분에는 주석을 단다.
- `TestController.cs`는 원본에서 **추가·변경한 곳**에 주석으로 표시한다.
