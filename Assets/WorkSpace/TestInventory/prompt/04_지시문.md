# 04 지시문 — 4단계: TestInventoryManager를 GameManager에 등록

## 배경
- 3단계까지 인벤토리는 정상 동작한다. 다만 `TestInventoryManager`가 **씬 오브젝트로 붙어 있고 GameManager에 등록되어 있지 않다.**
- 사용자가 이번 한 가지에 한해 **`GameManager.cs` 수정을 허용**했다. 다른 기존 매니저들과 같은 방식으로 `GameManager`가 `TestInventoryManager`를 생성·보유하게 만든다.
- 작업 위치: `D:\Unity_Project\3DverProject\Assets\WorkSpace\TestInventory` 및 BaseCopy의 `GameManager.cs`

## 절대 규칙
1. **수정이 허용된 기존 파일은 `GameManager.cs` 하나뿐**이다. 그 외 기존 매니저(UIManager, PoolManager, EventManager 등)와 기존 스크립트(원본 `Controller`, `InventoryUI`, `Game1Inventory` 등), 원본 씬은 수정·삭제·이동하지 않는다.
2. `GameManager.cs`는 **최소 수정**만 한다.
   - 기존 매니저들(`Resource/Pool/UI/Event/Sound/Unit`)이 생성·접근되는 **패턴을 그대로 따라** `TestInventoryManager`를 추가한다. (Awake에서 코드로 생성, `public static` 접근자)
   - 이 목적 외의 정리, 리팩터링, 이름 변경, 서식 변경은 하지 않는다.
   - 수정한 줄마다 **"5차 평가 인벤토리 추가"** 주석을 단다.
3. **`GameManager.cs`의 인코딩(CP949)과 줄바꿈(CRLF 등)을 그대로 유지한다.** 한글 주석이 깨지면 안 된다. 저장 후 기존 한글 부분이 그대로인지 확인한다. 인코딩을 유지한 채 수정할 방법이 없으면 **멈추고 보고**한다.
4. 새 `.cs` 파일은 UTF-8로 저장한다.
5. **컴파일 에러가 없는지까지만 확인한다.** (`read_console`) 플레이 테스트와 추가 점검은 하지 않는다. 사용자가 직접 한다.
6. 애매하거나 확실하지 않은 것은 임의로 판단하지 말고 결과 파일 "확인 필요"에 적고 그 지점에서 멈춘다.
7. 채팅 응답은 **"완료"** 한 단어만 한다. 작업 내용은 채팅에 설명하지 않는다.
8. 퀵슬롯 연동 등 추가 기능은 하지 않는다.

## 작업 1 — GameManager 등록
- `GameManager.cs`를 읽고, 자식 매니저 6개를 만드는 방식과 `public static` 접근자 패턴을 그대로 따른다.
- 추가할 것:
  - `TestInventoryManager`를 `Awake`에서 코드로 생성(기존 매니저와 같은 방식)
  - 접근자 `GameManager.TestInventory` (기존 접근자의 이름·형태 규칙을 따른다)
- **생성 범위**: 다른 매니저와 동일하게 **모든 씬에서 생성**한다. (씬 이름 조건을 달지 않는다.)
- `[DefaultExecutionOrder(-100)]`, `DontDestroyOnLoad`, 씬 전환 시 재생성(`Recreated` 등) 같은 **기존 흐름과 충돌하지 않는지** 확인하고, 충돌하면 임의로 해결하지 말고 "확인 필요"에 적는다.
- 중복 생성이 일어나지 않게 한다. (이미 있으면 새로 만들지 않는 기존 패턴이 있으면 그것을 따른다.)

## 작업 2 — TestInventoryManager를 코드 생성에 맞게 변경
GameManager가 코드로 만들면 씬 오브젝트와 인스펙터 연결이 사라지므로 아래를 처리한다.
- **우측 상단 버튼**: 인스펙터로 연결하던 `openButton`과 씬의 `TestInventoryButtonCanvas`를 없애고, `TestInventoryManager`가 **코드로 만들거나 `Resources` 프리팹에서 불러오게** 한다. (디자인·위치·동작은 3단계 그대로: 우측 상단, "인벤토리 / I", 클릭하면 열기/닫기, I 키와 같은 경로)
  - 프리팹을 새로 만든다면 `Assets\Resources\UI\` 아래에 두고, 경로를 결과 파일에 적는다. (이미 `TestInventoryWindow.prefab`이 있는 곳)
- **한글 폰트 등 인스펙터로 연결하던 값**이 있으면 코드에서 불러오도록 바꾼다. (예: `Resources.Load`, 또는 프리팹 안에 포함) 어느 방식을 썼는지 결과 파일에 적는다.
- **`TestInventoryScene.unity`**: 씬에 있던 `TestInventoryManager` 오브젝트와 `TestInventoryButtonCanvas`를 **삭제**해 중복 생성을 막는다. (원본 씬은 수정하지 않는다.)
- `TestController`가 `TestInventoryManager.IsOpen`을 읽는 방식은 `static`이므로 그대로 동작해야 한다. 바뀐 게 있으면 확인하고 맞춘다.
- 버튼용 Canvas는 UIManager가 만드는 Canvas/EventSystem과 **중복·충돌하지 않게** 한다. 3단계와 같은 구조(Overlay, Sorting 5)를 유지한다.
- 필수 기능, 옵션 2개, 닫기 버그 수정(`CloseWindowUI`를 쓰지 않고 SetActive로 끄고 켜는 방식, `try/finally` 복구)은 **그대로 유지**한다.

## 주석 갱신 (평가 대상)
- **`TestInventoryManager.cs` 맨 위 설계 메모 3종**을 바뀐 구성에 맞게 고친다.
  - `[기획 메모]`: GameManager에 등록한 이유(다른 매니저와 같은 방식으로 `GameManager.TestInventory`로 접근)
  - `[사용한 UI]`: 우측 상단 버튼을 코드/프리팹으로 생성하는 방식, 연결 방식
  - `[설계]`: 생성 시점(GameManager Awake), 접근 방법, 중복 생성 방지
- 수정한 모든 스크립트 맨 위의 "하는 일 / 붙인 오브젝트" 주석도 실제와 맞게 고친다. (`붙인 오브젝트`는 이제 "GameManager가 코드로 생성")
- `GameManager.cs`의 수정 줄에 **"5차 평가 인벤토리 추가"** 주석. (과제 규정: 기존 스크립트를 고쳤다면 고친 곳에 주석을 남긴다.)
