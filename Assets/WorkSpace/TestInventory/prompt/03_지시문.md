# 03 지시문 — 3단계: 버그 수정 / 디자인 변경 / 우측 상단 버튼

## 배경
- 2단계 구현 후 사용자가 `TestInventoryScene`을 플레이해 보고 아래를 확인했다.
  - 정상: I 키 열기/닫기, 커서 해제, 칸 선택(노란색 1칸, 텍스트), 칸 늘리기, 한글 표시
  - **버그**: 닫기 버튼을 누르면 아래 예외가 나고, 이후 캐릭터가 계속 멈춘 채 풀리지 않는다.

- 사용자의 추정 원인: 위 예외 때문에 `CloseWindow()`의 뒷부분(`IsOpen = false`, 커서 복구)이 실행되지 않아 `TestController`가 계속 입력을 막는다. 이 추정이 맞는지도 확인한다.

## 절대 규칙
1. **기존 매니저(GameManager, UIManager, PoolManager 등)와 기존 스크립트는 수정·삭제·이동하지 않는다.** 원본 `Controller`, `InventoryUI`, `Game1Inventory`, 원본 씬도 그대로 둔다.
2. 수정 대상은 **TestInventory 안의 파일과 `Resources\UI\TestInventoryWindow.prefab`** 뿐이다.
3. 새 `.cs` 파일은 UTF-8로 저장한다.
4. **컴파일 에러가 없는지까지만 확인한다.** (`read_console`) 플레이 테스트와 추가 점검은 하지 않는다. 사용자가 직접 한다.
5. 기존 매니저를 고치지 않고는 해결할 수 없다고 판단되면 **임의로 고치지 말고** 결과 파일 "확인 필요"에 원인과 선택지를 적고 그 지점에서 멈춘다.
6. 애매하거나 확실하지 않은 것도 임의로 판단하지 말고 "확인 필요"에 적는다.
7. 채팅 응답은 **"완료"** 한 단어만 한다. 작업 내용은 채팅에 설명하지 않는다.
8. 퀵슬롯(1~4번) 연동, 슬라임 드래그 같은 **추가 기능은 하지 않는다.** (사용자가 이번엔 하지 않기로 결정함)

## 작업 1 — 버그 수정 (가장 먼저)
1. `PoolManager.cs` 281행 부근(`CreateUIPool`의 해제 콜백)과 `ReleaseUI`, `UIManager.CloseWindowUI`, `UIManager.ShowWindowUI`를 **읽어서** 무엇이 null인지, 왜 `TestInventoryWindow` 프리팹/인스턴스에서만 null이 되는지 원인을 찾는다. (예: 풀이 기대하는 컴포넌트/자식/필드가 프리팹에 없음, 풀로 만들어지지 않은 인스턴스를 해제함, 이미 파괴된 오브젝트 참조 등)
2. 원인이 TestInventory 쪽(스크립트 또는 프리팹)에 있으면 거기서 고친다. 매니저가 요구하는 규칙이 있으면 프리팹/스크립트를 그 규칙에 맞춘다.
3. 원인이 **매니저 코드 자체**에 있어 수정 없이는 해결 불가하면, 우회 방법(예: 풀을 거치지 않는 방식)이 TestInventory 쪽만으로 가능한지 검토한다. 우회도 불가하거나 매니저를 쓰는 의미가 사라질 정도면 **멈추고 보고**한다.
4. **방어 처리**: `TestInventoryManager`의 열기/닫기에서, 창을 닫는 도중 예외가 나더라도 `IsOpen = false`와 커서 복구가 **반드시 실행**되도록 순서를 바꾸거나 `try/finally`를 쓴다. (정리 코드를 닫는 호출보다 먼저 실행하거나 finally에 둔다.)
5. 결과 파일에 **실제 원인 한 줄**과 **고친 방법 한 줄**을 적는다.

## 작업 2 — 디자인을 문서 그림대로 변경
기준 그림은 과제 안내서의 "완성 화면 예시"다. 모양과 색은 자유지만 아래 느낌을 따른다. (색은 제안값이며 비슷하면 된다.)

- **창 패널**: 어두운 남색(약 `#262B3A`), 연한 회색 테두리(약 `#6B7385`), **둥근 모서리**.
- **제목**: 왼쪽 위에 흰색 굵은 글씨 **"인벤토리"**.
- **닫기 버튼**: 오른쪽 위, **빨간색(약 `#D04545`) 둥근 사각형**에 흰색 굵은 **"X"**.
- **칸**: 어두운 회색 바탕(약 `#454B5C`) + 얇은 연한 회색 테두리(약 `#8A91A0`) + 둥근 모서리. 번호는 **칸의 왼쪽 위에 작은 회색 글씨**로 표시. (지금처럼 가운데 큰 글씨 아님)
- **선택된 칸**: **굵은 노란 테두리(약 `#F5C432`) + 올리브색 바탕(약 `#7A6B3A`)**. 한 번에 한 칸만.
- **하단 텍스트**: 왼쪽 아래. 선택 없음일 때 흰색 **"선택: 없음"**, 선택하면 노란색 **"선택: N번 칸"**.
- **확장 버튼과 안내 문구**: 같은 톤으로 패널 하단에 정돈해 배치한다. (선택 텍스트와 겹치지 않게)
- 칸은 4열 × 2줄(8칸)이 기본이고, 12칸·16칸으로 늘어나도 **패널 밖으로 넘치지 않게** 패널 크기와 배치를 조정한다. (필요하면 늘어날 때 패널 높이가 맞춰지거나 칸 크기를 줄이는 방식)
- 둥근 모서리용 스프라이트는 Unity 기본 UI 스프라이트(9-slice)를 쓴다. 불가능하면 사각형으로 두고 결과 파일에 적는다.
- 색 변경은 **기존처럼 선택할 때만** 한다. 매 프레임 갱신 금지.
- 디자인을 바꾼 뒤에도 **필수 기능과 옵션 2개**(칸 늘리기, 플레이어 연동)가 그대로 동작해야 한다.

## 작업 3 — 화면 우측 상단 인벤토리 버튼
- 게임 화면 **우측 상단**에 인벤토리 버튼을 항상 표시한다. 버튼 안에 **"인벤토리"** 와 키 안내 **"I"** 를 함께 보이게 한다.
- 기존 UI(점수 등 이미 화면에 있는 것)와 **겹치지 않는 위치**를 고른다. 기존 UI를 확인하고 위치를 정한다.
- 버튼을 누르면 인벤토리가 열린다. (이미 열려 있으면 닫기로 동작해도 된다. I 키와 같은 열기/닫기 경로를 사용해 상태가 어긋나지 않게 한다.)
- **주의**: 플레이 중에는 커서가 잠겨 있어 마우스로 누를 수 없다. 기존 `Controller`의 **LookOff 입력을 누르는 동안 커서가 풀리므로**, 그때 이 버튼을 클릭해 열 수 있으면 된다. 구현 시 아래를 확인한다.
  - 이 버튼과 열려 있는 창의 클릭이 EventSystem으로 정상 전달되는지
  - LookOff로 커서가 풀린 상태에서 인벤토리를 열었다 닫았을 때 `TestInventoryManager`의 커서 복구가 LookOff 상태와 충돌하지 않는지
  - 충돌하거나 애매하면 임의로 처리하지 말고 "확인 필요"에 적는다.
- 이 버튼은 **게임 화면에 항상 떠 있는 UI**이므로, 창을 닫으면 사라지는 `TestInventoryUI` 프리팹이 아니라 **항상 켜져 있는 쪽**(`TestInventoryManager`가 붙은 오브젝트 또는 그 아래의 별도 Canvas 등)에 둔다. 어떤 구조로 만들었는지는 설계 메모에 적는다.
- 이 버튼 때문에 씬에 새 Canvas/EventSystem이 필요하면 만들되, 기존 매니저가 만드는 Canvas/EventSystem과 **중복되거나 충돌하지 않게** 한다. 어려우면 멈추고 보고한다.

## 주석 갱신 (평가 대상)
- 구성이 바뀌므로 **`TestInventoryManager.cs` 맨 위 설계 메모 3종**을 실제와 맞게 고친다.
  - `[기획 메모]`: 우측 상단 버튼 추가와 이유, 디자인 방향(문서 그림 기준)
  - `[사용한 UI]`: 바뀐 프리팹 구성과 새로 만든 우측 상단 버튼 오브젝트, 붙인 컴포넌트, 연결한 것
  - `[설계]`: 닫을 때 예외가 나도 상태가 복구되도록 한 순서(방어 처리), 버튼과 I 키가 같은 열기/닫기 경로를 쓰는 점
- 수정한 모든 스크립트 맨 위의 "하는 일 / 붙인 오브젝트" 주석도 실제와 맞게 갱신한다.
